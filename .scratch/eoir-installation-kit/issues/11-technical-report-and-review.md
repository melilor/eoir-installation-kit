## Answer

Closed on 2026-09-18. `docs/report.md` is the technical report: eleven narrative chapters, the
results of every analysis with the finding that comes closest to its limit, the verification
register, the assumptions, the limitations register, the compliance and qualification frame, and
the review. It is generated by `tools/report.py` from `model/report.yaml` and from the evidence
files, so **no figure in it is typed**: each one is read from the artifact it comes from and the
table names the path, for example
`evidence/loads/checks.json → governing_case_by_check.LOADS-HARD-POINT.reaction_n`.

**The review, and what independence means here.** The review is executed by the same tool against
the *requirement and evidence model*, not against the prose, which is what the ticket asked for:
six review questions become 33 checks that run in the pipeline on every change. It is not
independent in the sense a certification programme means, because the study has one author, and
the report says so in the review chapter instead of letting the word suggest otherwise. That is
recorded as the one `INDEPENDENCE` class limitation of the register (`REVIEW`), and it is the
honest floor: a program that reads the files the author wrote is not a second engineer.

**The review found real things and they are fixed, not filed.**

| Finding | What happened |
| --- | --- |
| `README.md` and `docs/overview.md` quoted 150 tests where the suite had grown to 152 | Both updated; the count is now checked on every run, so it cannot drift again |
| The validator line quoted in `README.md` said 9 warnings where there are 12 | Updated, and the line is now a checked number |
| Two open items of the power analysis had no identifier, so the register could not name them | They are `OI-04` and `OI-05` now |
| Fourteen of the documented numbers were not checkable at all | They are declared as patterns in `model/report.yaml` and verified against the model or the evidence |
| `evidence/mass/checks.json` unreadable would have crashed the review instead of failing it | The reader returns nothing and the check fails, with a test that empties the file |

**The limitations register.** Thirty-four entries, each classified: **INPUT** (15 open assumptions
and two open items), **METHOD** (the resonance estimate, the plate and weld flexibility, the
closed-form limit of the study), **ARTICLE** (four cases that need a physical article), **AUTHORITY**
(eight that need the platform, the installer or the competent authority), **INDEPENDENCE** (the
review). The check runs in both directions: a limitation of the model without a class fails, and a
class that names nothing fails. No `WARN` was promoted: the register carries none, and a test sets
one on purpose to prove the check fires.

**Three findings the review produced by coupling, which are the point of it.** Removing an evidence
file also removes the number a document quotes from it, so two checks speak instead of one; a
status change moves the counts in the README, so the counts are checked rather than remembered;
